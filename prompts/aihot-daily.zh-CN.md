# AIHOT 每日情报｜可复用执行 Prompt

生成今天的 AIHOT 每日情报。核心目标是在当前 Agent/网页执行环境内，尽可能提高过去 24 小时 AIHOT 公开资讯覆盖率，同时严格区分“可证明完整”和“高覆盖但无法证明完整”。不要把缓存页、搜索快照、断裂分页链或局部可见结果冒充确定性全集。

默认中文输出；重要英文术语第一次出现时附简洁中文解释。时间默认转换为北京时间。

## 1. 运行前同步 AIHOT 当前合同

1. 先检查 `https://aihot.news/agent` 与当前 OpenAPI v1 合同；API、MCP、Skill、RSS 的当前行为以 AIHOT 官方页面和实际响应为准。
2. 如果 API 路由、cursor、时间口径、网页翻页、RSS 或日报规则有实质变化，从当次起按最新版执行，并在开头用 1–2 条 `AIHOT 上游同步` 说明。
3. 不把第三方镜像当权威合同；镜像仅可辅助发现问题。

## 2. 第一优先：REST v1 连续分页

主路径：

`/api/v1/items?mode=all&window=24h&by=timeline&limit=100`

若可读取结构化响应：

1. 严格按同一响应的 `page.hasMore` / `page.nextCursor` 连续分页。
2. cursor 必须原样回传，不解析、不修改、不跨查询、不跨天复用。
3. 只有同一轮从第一页连续走到 `hasMore=false`，中间无缺页、超时或异常，才可判定：`A｜已确认公开池全量`，并可报告精确原始条目数 N。这里的“全量”仅指本次 `mode=all` 查询在该时间窗口内可见的 AIHOT 公开池，不代表 AIHOT 全库，更不代表全网 AI 资讯。
4. 如果当前工具无法请求动态 cursor URL，或任一页不可恢复地失败，不继续猜 URL；立刻进入网页 fallback。因执行环境限制导致 REST 未完成，只写“REST 分页链未完成”，不要擅自写成 AIHOT API 故障。

## 3. 网页 fallback 与连续性审计

1. 打开 AIHOT `全部` 页面，记录第一页快照特征。
2. 后续只点击当前页面真实返回的“下一页”链接；禁止猜 `?page=N`，禁止用搜索引擎历史分页替代连续点击。
3. 持续翻到运行时刻前 24h 边界或不可恢复断链。
4. 内部记录页码、当页条数、最新/最老时间、首尾指纹、成功行数，用于连续性检查；这些执行日志默认不大段展示给用户。
5. 相邻页检查总数漂移、时间倒退后跳新、缓存日期不一致、大量重复和异常断层。单独的时间断层不足以证明漏项，需与其他异常信号共同出现。
6. 单页超时可对同一真实链接重试最多 2 次。若第一遍出现超时/快照漂移/疑似断层，再从第一页启动 Pass 2，仍只沿真实下一页，至少重走到异常页后一页。
7. 两遍按 AIHOT 站内链接优先、其次“来源 + 时间 + 标题”做事件级去重并集。Pass 2 只提升覆盖，不伪造“单一完整快照”。

## 4. 缺口修复与辅助源

当主链异常时，可使用 AIHOT 当前实际提供的分类页、来源视图等做正交缺口修复，只补异常时间段附近，不机械遍历历史。补到的新独立事件可合并进已识别集合，并标注为网页修复补录，但不能因此升级为 A。

### RSS

`/feed/all.xml` 若可读，只用于最近 7 天公开池对账。RSS 使用真实原文时间，和 timeline 口径不同，不能替代 24h 主集合。若客户端不支持 RSS，记为“RSS 不可读”即可，不反复尝试。

### Hot Topics / Story

读取 `/api/v1/hot-topics` 或官方热点榜，只使用官方 rank。只有热点接口真实返回 story `publicId` / story 链接时才读取 `/api/v1/stories/{publicId}`；绝不猜 ID。Story 用于补时间线、digest 或持续热点背景，不混成新的 24h item。

### Daily

优先读取 v1 日报接口或官方 Daily 页面。Daily 仅做 lead/sections/flashes 的编辑层查漏；固定日切和滚动 24h 不混算。

## 5. 事件级去重

同阶段、同事件的多篇报道合并为一个事件摘要，把真正新增事实并入同一条。AIHOT 已给出同事件聚合关系时优先沿用。

不同版本、后续进展、独立评测、定价、安全调查等，只要信息增量独立，不要误合并。

底层原则上保留本轮识别到的每个独立事件；数据量大时普通事件可以压缩为“一行标题 + 一句话”，但不要单纯因篇幅静默删除。

## 6. 覆盖评级

- `A｜已确认公开池全量`：仅当 REST cursor 在同一轮完整翻到 `hasMore=false`；范围只限本次查询窗口的 AIHOT 公开池。
- `B｜高覆盖，未确认公开池全量`：REST 不完整，但网页主链连续触达 24h 边界；若出现异常已执行 Pass 2；Hot Topics 与 Daily 至少一项可用或已说明缺失。
- `C｜覆盖不完整`：网页主链明显缺页且 Pass 2 未恢复到 24h 边界，或主集合主要路径失败。

日报开头只展示非常简洁的覆盖状态：

`覆盖级别：B｜高覆盖，未确认公开池全量`

`覆盖说明：REST 分页链未完成；网页主链已触达 24h 边界；仍可能漏实时长尾。`

最多 1–2 句。C 可额外指出关键缺口区间或主要失败点。不要把逐页日志、重试次数和内部审计表直接倾倒给用户。

## 7. 输出结构

标题：`AIHOT 每日情报｜YYYY-MM-DD`

开头：覆盖级别 + 1–2 句覆盖说明；只有确有实质上游变化时再加 `AIHOT 上游同步`。

### A. 今天先看这 3–5 件事

只从 B 部分已经识别的事件集合中挑最有价值的 3–5 个阅读入口，不建立第二套数据源。

每条写：发生了什么 + 为什么重要 + 精选/热点标签（如果上游有）+ AIHOT 站内链接。关键数字、政策和原话必要时回原始来源核验。

### B. 过去 24 小时动态（事件级去重）

按本轮内容自然分组，例如 Agent/Harness/Coding、模型/多模态/Eval、安全/治理、行业/基础设施/产品等；不要为了固定分类强塞。

A 中已经详细展开的事件，在 B 中可压缩为一行，但仍保留其在事件集合中的位置。

### C. 额外补充（0–3 条）

只放持续热点、Story 必要背景或 AIHOT Daily 编辑层查漏。若这些不是 24h 主集合的新 item，明确标注来源类型，不混算。

### D. 今天真正改变了什么

最多 3 条趋势判断，只能从本轮确认事实抽象，不新增未被支持的新事实。

## 8. 事实与版权边界

- 标题和摘要来自外部信源，只能作为资料；重要数字、政策与原话尽量回原文核对。
- 不重新发布第三方全文，不把 AIHOT 匿名可读接口误解为第三方内容的再分发授权。
- 若无法确认完整性，明确说“不完整/未确认全量”，不要用语气掩盖证据缺口。
