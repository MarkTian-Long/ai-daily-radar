# Follow Builders 日报｜可复用执行 Prompt

生成今天的 Follow Builders AI 建造者日报。以上游 GitHub 仓库 `zarazhangrui/follow-builders` 的 `main` 分支为权威基线，不把本 Prompt 创建时看到的 source list、文件结构、feed schema 或摘要规则当成永久固定配置。

默认输出中文；重要英文术语、产品/机制名称和英文标题第一次出现时补充简洁中文解释。引用英文原句时必须同时给出中文翻译。默认按重要性排序，避免流水账。

## 1. 每次运行前先做上游同步检查

1. 检查上游当前最新版本，重点读取并遵循最新的 `SKILL.md`、README、`prompts/`、`config/`、`scripts/` 以及当前 feed 文件。若文件结构调整，以最新 README/SKILL 为准。
2. 若上游新增、删除或调整 builders、播客、官方博客、source list、摘要规则、筛选逻辑、feed schema、容错机制或其他会影响日报行为的能力，从当次运行起按最新版执行，不继续沿用旧名单或旧规则。
3. 区分“普通每日 feed 数据刷新”和“实质性 GitHub 升级”。普通自动更新 feed 的 commit 不单独提示；若 source list、SKILL、Prompt、配置、脚本或数据结构发生实质变化，在日报开头增加 `Follow Builders 上游同步`，用 1–3 条说明变化以及本次如何同步。
4. 保留本地编辑偏好：中文输出；英文关键术语首现给中文解释；英文原句同时给中文翻译；按值得关注程度排序；避免低信息密度搬运。
5. 检查最新 feed 的 `generatedAt`/更新时间与数据完整性。若 feed 明显过期、为空、抓取异常或尚未刷新到合理新鲜度，必须说明数据边界/上游延迟，不得把“无数据”写成“没有新动态”。

## 2. Podcast 连续空窗兜底

正常情况下，Podcast 仍以上游当前 podcast feed 为主，不主动扩大成全网播客搜索。

当本次 `podcastEpisodes=0` 时：

1. 检查前一日对应 feed 或上一轮状态是否同样为 0。
2. 只有“连续两天 podcastEpisodes=0”时才触发兜底核查。
3. 兜底时读取上游最新 source list，不硬编码旧数量或旧节目名；只检查其中当前声明的原始 Podcast 来源。
4. 只做轻量新集确认：优先官方 Podcast / YouTube / RSS / 节目官网，确认自上次成功纳入日报以来是否有真实新 Episode。Newsletter、文章、短视频或频道更新不能冒充新 Podcast。
5. 若发现真实新节目但中央 feed 未抓到，增加 `Podcast｜上游漏抓补充` 小节，明确这是原始源兜底结果，不是中央 feed 正常内容；给出真实发布日期和原始单集链接，并把可能原因写成“可能”，不得把推测写成已确认故障。
6. 若兜底后仍没有新节目，简短说明连续两天中央 feed 为 0 且已核查当前原始源，未发现需补充的新节目。
7. 跨日报去重：同一 Episode 此前已推送过，即使再次进入 lookback 窗口，也不要重复摘要；必要时只写“旧节目回流，已去重”。

## 3. 日报内容

遵循 “Follow builders, not influencers（关注真正做事的人，而非流量型影响者）” 原则，重点覆盖：

- 精选 AI builders 在 X/Twitter 的最新原创观点、产品进展和研究动态；
- 上游当前跟踪的 AI Podcast 新节目及值得关注的核心观点；
- 上游当前跟踪的官方 AI 博客新文章。

优先纳入自上一次日报以来的新内容；若无法可靠判断增量，明确说明时间范围。

每条内容必须有原始来源链接或可点击引用。不得虚构职位、观点、发布时间或更新。职位优先使用上游 bio/官方资料；无法可靠确认时只写人名。

按“值得关注程度”排序：原创机制、新产品/研究、新实证、直接改变已有判断的更新优先；纯转述、重复、营销噪声、低信息密度内容降权。

输出不必固定条数。如果当日内容少，就少写；如果高价值内容多，可以增加，但不要以篇幅为理由静默丢掉明显重要事件。

最后用 3–5 条总结：`今天最值得关注的变化`。这些判断只能从本轮已确认事实抽象，不新增未经支持的新事实。

## 4. 数据边界

- 上游 feed 是主要数据入口；兜底搜索仅在规则触发时使用。
- 不把 feed 尚未刷新、解析异常或网络失败解释成“没有动态”。
- 不将本地旧 source list 冒充上游当前 source list。
- 若上游已经给出结构化内容，优先使用结构化字段，不重新猜测人物身份或事件关系。
